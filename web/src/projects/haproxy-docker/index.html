HAProxy Lab (Docker)

Reverse Proxy & Load Balancing with Nginx

A hands-on lab demonstrating reverse proxying and load balancing using HAProxy with two Nginx containers. The environment implements round-robin load balancing, backend health checks, HTTP-to-HTTPS redirect, SSL termination, and domain-based access through Docker Compose.

01. PROJECT OBJECTIVE

Why I Built This Lab

The goal of this project is to understand how a load balancer distributes incoming traffic across multiple backend servers and how HAProxy can be used as a reverse proxy in a containerized environment.

The lab also provides hands-on practice with Docker networking, health checks, DNS, SSL/TLS, and troubleshooting traffic between frontend and backend services.

03. DOCKER COMPOSE ENVIRONMENT

Three-Container Topology

Docker Compose runs one HAProxy container and two Nginx backend containers on the same bridge network, lab-net. The Nginx document roots are mounted read-only from separate host directories.

services:
  web1:
    image: nginx:alpine
    volumes:
      - ./web/web1:/usr/share/nginx/html:ro
    networks: [lab-net]

  web2:
    image: nginx:alpine
    volumes:
      - ./web/web2:/usr/share/nginx/html:ro
    networks: [lab-net]

  haproxy:
    image: haproxy:2.9-alpine
    ports: ["80:80", "443:443", "8404:8404"]
    networks: [lab-net]

04. HAPROXY CONFIGURATION

Frontend, Backend & Health Checks

HAProxy accepts HTTP and HTTPS traffic, redirects HTTP to HTTPS, terminates TLS on port 443, forwards the client address, and distributes requests to WEB01 and WEB02 using round-robin.

frontend fe_web
    bind *:80
    bind *:443 ssl crt /usr/local/etc/haproxy/certs/lab.khakim-projects.xyz.pem
    http-request redirect scheme https unless { ssl_fc }
    option forwardfor
    default_backend be_web

backend be_web
    balance roundrobin
    option httpchk GET /
    server web1 web1:80 check
    server web2 web2:80 check

listen stats
    bind *:8404
    stats enable
    stats uri /stats
    stats refresh 5s

07. HAPROXY LOGS

Traffic & Backend State

The HAProxy logs show requests being served by be_web/web1 and be_web/web2. They also capture WEB01 transitioning DOWN after a Layer 4 timeout and returning UP after a successful Layer 7 HTTP check.

Traffic distribution and backend health events. Click image to open the 4K version.
08. HEALTH CHECK & FAILOVER

Backend Failure Test

The logs demonstrate that HAProxy detected WEB01 as unavailable while WEB02 remained active. During that state, traffic continued through the healthy backend. After WEB01 recovered and passed the HTTP health check, both backends became available again.

WEB01 DOWN→HAProxy Health Check→WEB02 serves traffic→WEB01 UP

Observed in the lab log: Layer4 timeout → WEB01 DOWN, followed by Layer7 check passed, code 200 → WEB01 UP.

09. SSL/TLS & DNS

HTTPS Request Path

DNS A Record→VPS :443→HAProxy TLS Termination→WEB01 / WEB02 :80

HTTP traffic on port 80 is redirected to HTTPS. HAProxy terminates TLS using the certificate configured in the container and forwards HTTP requests to the internal Nginx backends.
